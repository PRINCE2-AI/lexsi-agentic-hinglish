Teaching Tiny Aya to split Hinglish expenses without losing the ledger

## Problem statement

Track 3, primary: **Reliable tool calling** — train an agent with RL on real tool-calling rollouts to choose the right tool, pass well-formed arguments, and call tools in the right order.

Track 3, secondary: **Efficient trajectories** — cut redundant, looping, or failed tool calls and the number of steps per task without lowering the success rate.

Every clause is scored mechanically: tool choice (`tac`), argument validity (`ter`/`arr`), ordering (final ledger correctness), redundancy (`rad`), looping (`lcf`), and steps per task (`calls`/`steps` mean).

## Problem

Cohere Labs models do not render `tools` in their chat template, and a 3.35B multilingual model has to carry a JSON ledger across turns while doing currency conversion and arithmetic. In Hinglish. This is a real reliability problem, not a toy.

## Why Hinglish

Aya is multilingual; most agent benchmarks are English. Hinglish expense splitting is a natural task for Indian roommates, and success is a deterministic ledger state, so it can be checked without an LLM judge.

## Method

1. Five stateless tools: `add_expense`, `convert_currency`, `get_balance`, `settle_up`, `finish`.
2. [N] hand-written Hinglish tasks; expected balances generated by the oracle.
3. Baseline: `CohereLabs/tiny-aya-global`, 4-bit, [decoding settings].
4. Post-training: AgentTune `create_agentic_trainer` with GRPO; LoRA r=16, [steps], [batch], [completion length]. Rewards: format, required tools, answer number, and [optional] a no-duplicate-calls term for the efficiency statement.
5. Evaluation: AuditKIT agent eval plus deterministic ledger checks.

## Metrics and why

| Code | Meaning | Why it matters |
|---|---|---|
| success | final ledger matches expected | the task is actually solved |
| tac | required tools called | no shortcut answers |
| arr / ter | argument reliability / tool errors | the model can use the schema |
| rad | redundant calls | cost and latency |
| lcf | loop collapse | agent gets stuck |
| strict / strict_rate | bare JSON turns | format is actually usable without a parser |
| calls / steps | tool calls and turns per task (mean) | trajectory efficiency |

## Limitations

- 20-task starter set; small sample, so report counts as well as percentages.
- Fixed offline FX rates; no live prices.
- Fixed six-person universe; no free-form names.
- Ledger must be copied by the model; a tool-side session store would remove that burden but hide the failure mode.
